## 2. FDA 510(k) 路径

### 2.1 产品分类

根据 FDA 产品分类规则：

```
产品代码: 90 IYO (Medical Image Display)
设备类别: Class II
审查途径: 510(k) Premarket Notification
```

### 2.2 预期用途声明

> "AI Adaptive Medical Display System 是一款医用显示器辅助设备，用于在医疗机构中显示医学影像。该设备通过AI技术自动识别影像模态并调整显示参数，辅助医疗专业人员查看和诊断医学影像。本设备不用于独立诊断，也不替代专业医疗人员的判断。"

### 2.3 实质等效对比

| 对比项目 | 申报设备 | 参照设备 (KXXXXXXXX) |
|----------|----------|---------------------|
| 预期用途 | 医学影像显示辅助 | 医学影像显示 |
| 显示技术 | LCD + AI优化 | LCD |
| 色彩管理 | DICOM GSDF | DICOM GSDF |
| AI功能 | 影像模态识别 | 无 |
| 网络连接 | 有 | 有 |
| 监管分类 | Class II | Class II |

### 2.4 性能测试要求

| 测试项目 | 方法 | 接受标准 |
|----------|------|----------|
| 亮度均匀性 | AAPM TG18 | ±20% |

| 色彩准确性 | AAPM TG18 | Delta E < 5 |

## 5. AI增强合规边界

### 5.1 AI辅助 vs AI诊断

```
┌─────────────────────────────────────────────────────────────┐
│                    AI功能边界定义                           │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│   ┌─────────────────────────────────────────────────────┐  │
│   │              AI辅助功能 (允许)                       │  │
│   │  • 自动识别影像模态                                 │  │
│   │  • 推荐显示参数                                     │  │
│   │  • 色彩/亮度自动优化                                │  │
│   │  • 局部区域增强提示                                 │  │
│   └─────────────────────────────────────────────────────┘  │
│                            │                                │
│                            │ 用户始终保留最终判断权          │
│                            ▼                                │
│   ┌─────────────────────────────────────────────────────┐  │
│   │              AI诊断功能 (禁止)                       │  │
│   │  • 自动识别病灶                                     │  │
│   │  • 生成诊断结论                                     │  │
│   │  • 提供治疗建议                                     │  │
│   │  • 替代医生判断                                     │  │
│   └─────────────────────────────────────────────────────┘  │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### 5.2 透明度要求

根据 FDA AI/ML 指南和 EU AI Act：

| 要求 | 实现方式 |
|------|----------|
| 算法说明 | 用户手册包含AI功能说明 |
| 训练数据 | 公开训练数据集来源 |
| 性能指标 | 精度/召回率测试报告 |
| 置信度 | 显示识别置信度 |
| 偏差评估 | 多医院数据集测试 |
| 人工监督 | 始终需要用户确认 |

### 5.3 审计追溯

| 数据类型 | 保留期限 | 内容 |
|----------|----------|------|
| AI推理日志 | 5年 | 时间戳、输入、输出、置信度 |
| 参数变更记录 | 永久 | 修改人、时间、参数值 |
| 用户操作记录 | 3年 | 操作类型、结果 |
| 系统事件 | 5年 | 错误、警告、信息 |

## 6. 质量管理体系

### 6.1 ISO 13485 认证

```
质量管理体系范围:
├── 产品设计开发
├── 生产制造
├── 安装服务
├── 售后服务
└── 供应商管理
```

### 6.2 关键过程

| 过程 | 输入 | 输出 | 验证方法 |
|------|------|------|----------|
| 设计输入 | 市场需求 | 需求规格 | 评审 |
| 设计验证 | 需求规格 | 测试报告 | 测试 |
| 设计确认 | 用户需求 | 临床验证 | 临床评估 |
| 设计转换 | 设计规格 | 生产文件 | 评审 |
| 生产控制 | 生产规格 | 产品 | 检验 |
| 不良事件 | 事件报告 | CAPA | 调查 |

### 6.3 CAPA 管理

| 项目 | 要求 |
|------|------|
| 问题识别 | 不良事件、投诉、审核发现 |
| 根本原因分析 | 5 Why、鱼骨图 |
| 纠正措施 | 消除原因 |
| 预防措施 | 预防类似问题 |
| 效果验证 | 有效性评审 |
| 文档记录 | 完整追溯 |

## 7. 临床评估

### 7.1 评估路径

根据 MDR Article 61 和 Annex XIV：

```
临床评估路径选择:
│
├── 等效路径 (Article 61.5)
│   ├── 技术特性相似
│   ├── 生物特性相似
│   ├── 使用条件相似
│   └── 临床数据可用
│
└── 自主临床数据路径
    ├── 临床调查
    ├── 前瞻性研究
    └── 回顾性数据分析
```

### 7.2 性能验证

| 测试类型 | 样本量 | 验收标准 |
|----------|--------|----------|
| 模态识别准确率 | 1000+ | > 95% |
| 显示一致性 | 100 | Delta E < 3 |
| 响应时间 | 连续1小时 | < 20ms 99% |
| 色彩稳定性 | 8小时 | Delta E < 2 |

### 7.3 可用性测试

根据 IEC 62366-1:

- 用户研究: 20+ 用户
- 使用场景: 典型临床环境
- 任务完成率: > 95%
- 使用错误: 无严重错误

## 8. 持续合规

### 8.1 上市后监督 (PMS)

| 活动 | 频率 | 责任人 |
|------|------|--------|
| 不良事件监测 | 持续 | 质量部 |
| 投诉分析 | 月度 | 客服部 |
| 趋势分析 | 季度 | 质量部 |
| 定期安全报告 (PSUR) | 年度 | 法规部 |
| 临床随访 | 按需 | 临床部 |

### 8.2 变更管理

根据 FDA 21 CFR Part 807 和 EU MDR Article 120:

| 变更类型 | 评估要求 |
|----------|----------|
| 重大设计变更 | 新510(k)/CЕ |
| 次要变更 | 内部评估+文档 |
| 制造变更 | 变更通知 |
| 软件更新 | 变更评估 |

### 8.3 警戒系统

```
不良事件报告流程:
│
├── 发现事件
│   └── 记录详细信息
│       ├── 时间、地点
│       ├── 设备信息
│       ├── 患者信息(如适用)
│       └── 事件描述
│
├── 初步评估
│   └── 严重性判定
│       ├── 严重事件 → 立即报告
│       └── 非严重事件 → 定期报告
│
├── 根本原因分析
│   └── 5 Why, Fishbone
│
├── CAPA实施
│   └── 纠正+预防
│
└── 关闭验证
    └── 有效性确认
```
